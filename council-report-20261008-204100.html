Detailed Advisor Briefings

1. The Contrarian Security & Exploitation Lens +

Primary Finding: The website is vulnerable to immediate administrative takeover via the Remember Me cookie implementation in includes/functions.php (lines 231-246). The script reads $_COOKIE['remember_token'], decodes base64, splits on a colon, and authenticates the user ID with zero cryptographic verification of the token hash!

Second Exploit: In admin/hero_slides.php (lines 157-160) and admin/manage_home.php, files are uploaded directly using their client-supplied extension into web-executable folders (assets/images/uploads/). Uploading a file named backdoor.php yields instant Remote Code Execution.

Third Risk: Plaintext production database credentials (u167160735_newdry, NewDry@123) and Hostinger SMTP credentials (contact@driyum.com, Driyum@123) are committed directly into the Git repository in config/database.php.

2. The First Principles Thinker Money, Inventory & State Invariants +

Primary Finding: Inventory decrement in checkout.php (line 327) executes UPDATE products SET stock = stock - ? WHERE id = ? without an AND stock >= ? condition. When multiple shoppers buy simultaneously, stock drives negative (-1, -2), forcing the store into unfulfilled backorders.

Payment Desync: Razorpay payments that complete when a user drops connection before the frontend JS redirects to form.submit() are captured via api/razorpay_webhook.php. However, the webhook handler updates the order status to paid without ever decrementing stock!

Historical Corruption: When an admin deletes a product in admin/inventory.php, it performs a hard SQL DELETE. But invoice.php and track.php perform an INNER JOIN products. Deleting a product wipes it out from past customer invoices and live order tracking.

3. The Expansionist Scale, Traffic Surges & Bottlenecks +

Primary Finding: In checkout.php (line 346), send_order_confirmation($order_id) executes a synchronous TLS connection to smtp.hostinger.com:465 inside the customer's HTTP request before redirecting to order-success.php. When SMTP latency spikes, customer checkouts hang for 10-30 seconds, generating high bounce rates and duplicate checkout clicks.

Table Bloat: Every checkout attempt creates an order row in orders. 10,000 abandoned checkouts create 10,000 zombie draft rows, degrading auto-increment IDs and slow-down admin queries.

Indexing Gap: Key lookup columns like orders.order_number, orders.user_id, and products.slug lack compound indexes, leading to full-table scans under high visitor volume.

4. The Outsider Customer Friction & Trust Lens +

Primary Finding: In invoice.php (lines 38-41), paying customers are blocked from viewing or downloading their invoice with the error: "Your order has not been confirmed yet. Invoice is available once processed." When a shopper spends ₹1,500 and cannot get a receipt, their first reaction is panic and bank dispute/chargeback.

Data Leak: In invoice.php (line 29), guest verification checks trim($contact) === trim($order_phone). If an order has an empty phone string, requesting invoice.php?id=...&contact= allows anyone to see the full customer invoice and shipping address.

Threshold Discrepancy: The top announcement banner displays "Free Shipping over ₹499" (hardcoded in head.php), but cart.php calculates free shipping starting at ₹500, causing confusion at checkout.

5. The Executor Immediate Engineering Roadmap +

Implementation Strategy:

  1. Step 1: Patch includes/functions.php Remember Me cookie handling immediately.
  2. Step 2: Add file extension whitelist in admin/hero_slides.php and admin/manage_home.php.
  3. Step 3: Update stock query in checkout.php with atomic guard: UPDATE products SET stock = stock - ? WHERE id = ? AND stock >= ?.
  4. Step 4: Update api/razorpay_webhook.php to decrement stock upon webhook receipt.
  5. Step 5: Remove invoice download restriction in invoice.php.
  6. Step 6: Decouple Hostinger SMTP into the existing email_queue table via background cron.
